## ۱. دادهٔ گمشده (Missing data)

در هر پژوهش واقعی بعضی مقادیر ثبت نمی‌شوند: نمونهٔ خون همولیز شد، بیمار پیش از آزمایش ترخیص شد، پرسش‌نامه ناقص ماند. **مهم این است که گمشده بودن را درست ثبت کنیم** تا نرم‌افزار آن را با یک مقدار واقعی اشتباه نگیرد.

### روش‌های ثبت مقدار گمشده

| روش | مثال | ارزیابی |
|---|---|---|
| خانهٔ خالی | `12.5,,7.1` | خوب و ساده؛ همهٔ نرم‌افزارها آن را گمشده می‌خوانند. |
| کد ویژه | `-99`، `999` | مفید وقتی **دلیل** گمشدگی مهم است (مثلاً ‎-99 = اندازه‌گیری نشد، ‎-98 = بیمار امتناع کرد). **حتماً** باید در کدبوک نوشته و در نرم‌افزار تعریف شود. کد باید خارج از بازهٔ مقادیر ممکن باشد. |
| `NA` | `12.5,NA,7.1` | استاندارد R؛ pandas هم آن را می‌شناسد. |
| **صفر** | `0` | **هرگز!** صفر یک مقدار واقعی است (CRP = 0 یعنی CRP بسیار پایین). |
| متن آزاد | `؟`، `ندارد`، `-` | بد؛ کل ستون عددی را متنی می‌کند. |

### خطرِ کد تعریف‌نشده: یک مثال واقعی از دادهٔ همین ماژول

در `M01_uti.csv`، CRP دو بیمار (شمارهٔ ۷ و ۱۹) اندازه‌گیری نشده و با `-99` ثبت شده است. اگر به نرم‌افزار نگوییم ‎-99 «گمشده» است:

| | n | میانگین CRP (mg/L) |
|---|---|---|
| ‎-99 به‌عنوان عدد واقعی | 30 | **35.10** |
| ‎-99 به‌عنوان گمشده | 28 | **44.68** |

دو عدد غیرواقعی میانگین را نزدیک **۱۰ واحد** پایین آورده‌اند! محاسبه:
- مجموع ۲۸ مقدار واقعی = 44.68 × 28 ≈ 1251
- با دو ‎-99: ‏(1251 − 198) / 30 = 1053 / 30 = **35.1**

این دقیقاً همان چیزی است که در تمرین عملی ع۳ در نرم‌افزار خودتان می‌بینید. **قاعده:** پس از وارد کردن هر فایل، کمینه و بیشینهٔ هر متغیر کمّی را نگاه کنید؛ عددی مثل ‎-99 یا 999 فوراً خودش را نشان می‌دهد.

### گمشدهٔ سیستمی و گمشدهٔ تعریف‌شده (اصطلاح SPSS)

- **System-missing:** خانهٔ خالی که SPSS با یک نقطه (`.`) نشان می‌دهد.
- **User-missing:** مقداری مثل ‎-99 که کاربر در ستون Missing در Variable View تعریف کرده است. مقدار در فایل می‌ماند ولی در محاسبات کنار گذاشته می‌شود.

در R و Python فقط یک نوع گمشده (`NA` / `NaN`) هست؛ کدهایی مثل ‎-99 را باید خودتان به آن تبدیل کنید.

### چرا داده گم شده است؟ (پیش‌درآمد M62)

| سازوکار | معنا | مثال |
|---|---|---|
| **MCAR** — کاملاً تصادفی | گمشدگی به هیچ چیز ربط ندارد | لولهٔ نمونه در آزمایشگاه شکست. |
| **MAR** — تصادفی (به شرط متغیرهای ثبت‌شده) | گمشدگی به متغیرهای **ثبت‌شده** ربط دارد | CRP بیماران بخش جراحی کمتر اندازه‌گیری می‌شود (بخش را داریم). |
| **MNAR** — غیرتصادفی | گمشدگی به **خود مقدار گمشده** ربط دارد | بیماران بدحال پیش از آزمایش به ICU منتقل شدند و CRP بالایشان ثبت نشد. |

اگر داده MCAR نباشد، حذف ساده سطرهای ناقص (Complete-case analysis، کاری که نرم‌افزارها به‌طور پیش‌فرض انجام می‌دهند) می‌تواند نتیجه را **سوگیرانه** کند. در این ماژول فقط باید گمشدگی را **درست ثبت و شمارش** کنید؛ روش‌های برخورد با آن در M62 می‌آید. در گزارش مقاله همیشه تعداد مقادیر گمشدهٔ هر متغیر را بنویسید.

## ۲. خطای اندازه‌گیری (Measurement error)

هر اندازه‌گیری = **مقدار واقعی + خطا**. خطا دو نوع است:

| | خطای تصادفی (Random) | خطای نظام‌مند (Systematic / Bias) |
|---|---|---|
| تعریف | نوسان غیرقابل‌پیش‌بینی، گاهی بالا گاهی پایین | انحراف ثابت در یک جهت |
| مثال | تکرار CRP یک نمونه: 44.1، 45.3، 44.8 | دستگاهی که کالیبره نیست و همیشه ۵ واحد بیشتر نشان می‌دهد |
| اثر روی میانگین گروه | با افزایش n کم می‌شود | با افزایش n **کم نمی‌شود** |
| اثر روی تحلیل | پراکندگی را زیاد و توان را کم می‌کند | نتیجه را جابه‌جا (سوگیرانه) می‌کند |
| ویژگی مرتبط | **دقت / تکرارپذیری** (Precision) | **صحت** (Accuracy / Trueness) |

```
    دقیق و صحیح          دقیق ولی ناصحیح       نادقیق ولی صحیح(به‌طور میانگین)
    ┌─────────┐           ┌─────────┐           ┌─────────┐
    │    ◎    │           │ ••  ◎   │           │ •   ◎ • │
    │   •••   │           │ ••      │           │    •    │
    │         │           │         │           │ •     • │
    └─────────┘           └─────────┘           └─────────┘
   (◎ = مقدار واقعی، • = اندازه‌گیری‌ها)
```

**نکته:** افزایش حجم نمونه فقط خطای تصادفی را جبران می‌کند. هیچ روش آماری نمی‌تواند سوگیری اندازه‌گیری را که از آن خبر نداریم برطرف کند؛ راه‌حل آن کالیبراسیون، کنترل کیفیت و طراحی درست است. ارزیابی تکرارپذیری و توافق روش‌ها در M43 (ICC، Bland–Altman) آموزش داده می‌شود.

## ۳. جمع‌بندی درس

- گمشده را با خانهٔ خالی یا کد ویژهٔ مستند ثبت کنید، هرگز با صفر.
- پس از ورود داده، کمینه/بیشینه و تعداد گمشده‌ها را بررسی کنید.
- خطای تصادفی ← دقت؛ خطای نظام‌مند ← صحت. n بزرگ‌تر فقط اولی را درمان می‌کند.

---

## مثال‌های حل‌شده

**مثال ۱ — گمشده با کد ۹۹۹.** وزن ۵ بیمار (kg): `72, 999, 65, 80, 999`. کدبوک: «999 = وزن نشد».
- بدون تعریف کد: (72 + 999 + 65 + 80 + 999) / 5 = 2215 / 5 = **443 kg** ← غیرممکن!
- با تعریف کد: (72 + 65 + 80) / 3 = 217 / 3 = **72.3 kg** با n = 3.

**مثال ۲ — سازوکار گمشدگی.** در یک کارآزمایی دارویی ضدافسردگی، بیمارانی که حالشان بدتر شده بود جلسات پیگیری را ترک کردند. نمرهٔ افسردگی پایانی آن‌ها ثبت نشد ← گمشدگی به **خود مقدار گمشده** (نمرهٔ بد) بستگی دارد ← **MNAR**. تحلیل فقط با بیماران باقی‌مانده، اثر دارو را **بیش از واقع** نشان می‌دهد.

**مثال ۳ — دقت و صحت.** یک ترازوی نوزاد ۵ بار یک وزنهٔ استاندارد ۳٫۰۰۰ kg را وزن کرده: 3.152، 3.149، 3.151، 3.150، 3.148. میانگین ≈ 3.150 ← اندازه‌ها بسیار نزدیک به هم‌اند (**دقیق**) ولی همه حدود ۱۵۰ گرم بیشترند (**ناصحیح، سوگیری +0.15 kg**). راه‌حل: کالیبراسیون، نه وزن‌کردن بیشتر.

### سطح ۲ — متوسط

**تمرین ۱.۴.۴** — مقادیر سدیم سرم (mmol/L) شش بیمار: `138, 141, -99, 136, 0, 140`. در کدبوک آمده: «‎-99 = اندازه‌گیری نشد». مقدار 0 را هم دستیار پژوهش برای «نمونه همولیز شد» وارد کرده است.
(الف) میانگینی که نرم‌افزار بدون هیچ تنظیمی حساب می‌کند چقدر است؟
(ب) میانگین درست چقدر است؟
(ج) مشکل مقدار 0 چیست و چطور باید ثبت می‌شد؟

<details>
<summary><b>حل</b></summary>

**(الف)** همهٔ ۶ عدد حساب می‌شوند:
مجموع = 138 + 141 + (−99) + 136 + 0 + 140 = 456 ← میانگین = 456 / 6 = **76.0 mmol/L** (از نظر فیزیولوژیک غیرممکن؛ سدیم طبیعی حدود ۱۳۵ تا ۱۴۵ است).

**(ب)** هم ‎-99 و هم 0 در واقع گمشده‌اند. مقادیر معتبر: 138، 141، 136، 140 (n = 4)
مجموع = 555 ← میانگین = 555 / 4 = **138.75 mmol/L**

**(ج)** صفر یک عدد واقعی است (سدیم صفر!) و نرم‌افزار راهی برای تشخیص آن از مقدار واقعی ندارد. باید با کد گمشدهٔ جداگانه و مستند ثبت می‌شد، مثلاً «‎-98 = نمونه همولیز شد»، تا هم گمشده شناخته شود و هم دلیلش حفظ شود. کنترل کمینه/بیشینه این خطا را فوراً نشان می‌داد.

</details>

**تمرین ۱.۴.۵** — سازوکار احتمالی گمشدگی (MCAR / MAR / MNAR) را در هر مورد تعیین کنید:
(الف) دستگاه آنالایزر یک روز کامل خراب بود و نمونه‌های آن روز آزمایش نشدند.
(ب) در یک مطالعهٔ کاهش وزن، افرادی که وزن اضافه کرده بودند برای وزن‌کشی پایانی مراجعه نکردند.
(ج) سالمندان بیشتر از جوانان پرسش‌نامه را ناقص گذاشتند و سن همهٔ شرکت‌کنندگان ثبت شده است.
(د) در پیمایش درآمد خانوار، افراد پردرآمد کمتر به سؤال درآمد پاسخ دادند.

<details>
<summary><b>حل</b></summary>

- **(الف) MCAR:** خرابی دستگاه به ویژگی بیماران ربطی ندارد (به شرط آنکه بیماران آن روز با روزهای دیگر فرقی نداشته باشند).
- **(ب) MNAR:** گمشدگی به **خود مقدار گمشده** (وزن پایانی بالا) بستگی دارد. حذف این افراد اثر برنامه را بیش از واقع نشان می‌دهد.
- **(ج) MAR:** گمشدگی به سن ربط دارد و سن **ثبت شده** است؛ پس می‌توان با روش‌هایی مثل جایگزینی چندگانه (M62) آن را اصلاح کرد.
- **(د) MNAR:** پاسخ‌ندادن به خود درآمد (مقدار گمشده) بستگی دارد؛ میانگین درآمد پاسخ‌دهندگان کمتر از واقع است.

</details>

**تمرین ۱.۴.۶** — دستگاه گلوکومتر یک درمانگاه همیشه ۱۰ mg/dL کمتر از مقدار واقعی نشان می‌دهد. پژوهشگر می‌گوید: «نگران نیستم، حجم نمونه را از ۱۰۰ به ۱۰۰۰ نفر می‌رسانم.» آیا این کار مشکل را حل می‌کند؟ چرا؟

<details>
<summary><b>حل</b></summary>

**خیر.** این **خطای نظام‌مند (سوگیری)** است، نه تصادفی:
- با ۱۰۰ نفر، میانگین اندازه‌گیری‌شده ≈ میانگین واقعی − 10.
- با ۱۰۰۰ نفر، میانگین اندازه‌گیری‌شده **باز هم** ≈ میانگین واقعی − 10، فقط با اطمینان بیشتر!

افزایش n فقط نوسان تصادفی را کم می‌کند؛ یعنی پژوهشگر با اطمینان بیشتر به عدد **غلط** می‌رسد. راه‌حل: کالیبراسیون دستگاه با محلول استاندارد یا اندازه‌گیری مقایسه‌ای با روش مرجع (M43).

(نکته: اگر هدف فقط **مقایسهٔ دو گروه** با همین دستگاه باشد، خطای ثابت ۱۰ واحدی در هر دو گروه یکسان است و از تفاضل حذف می‌شود؛ ولی برای گزارش مقدار مطلق یا مقایسه با مرز تشخیص دیابت، مشکل جدی است.)

</details>

**تمرین ۱.۴.۷** — در یک فایل، ستون `pregnant` برای مردان خالی مانده و ستون `organism` برای بیمارانی که کشتشان منفی بوده خالی است. آیا این خانه‌ها «گمشده» هستند؟ چطور باید کدگذاری شوند؟

<details>
<summary><b>حل</b></summary>

1. این خانه‌ها **گمشده نیستند**؛ مقدار وجود ندارد چون سؤال برای آن فرد **کاربرد ندارد** (Not applicable).
2. اگر هر دو را خانهٔ خالی بگذاریم، نرم‌افزار آن‌ها را با «گمشدهٔ واقعی» (مثلاً زنی که وضعیت بارداری‌اش ثبت نشده) یکی می‌کند و درصد گمشدگی را غلط گزارش می‌کند.
3. **کدگذاری پیشنهادی:** یک کد جدا، مثلاً `-88 = کاربرد ندارد`، و `-99 = نامعلوم/ثبت‌نشده`؛ هر دو در کدبوک و هر دو در نرم‌افزار به‌عنوان گمشده تعریف شوند (تا در محاسبه وارد نشوند)، ولی در گزارش جدا شمرده شوند.
4. هنگام تحلیل، مخرج درصد باید درست باشد: «درصد زنان باردار» از میان **زنان**، نه همهٔ بیماران.

</details>

### سطح ۳ — پیشرفته

**تمرین ۱.۴.۸** — CRP یک نمونهٔ کنترل کیفی با مقدار واقعی ۵۰ mg/L، پنج بار در دو آزمایشگاه اندازه‌گیری شده است:
آزمایشگاه A: 49.8، 50.3، 50.1، 49.9، 50.2
آزمایشگاه B: 44.0، 57.5، 51.2، 46.3، 52.0
میانگین هر آزمایشگاه را حساب کنید و هر کدام را از نظر دقت و صحت ارزیابی کنید.

<details>
<summary><b>حل</b></summary>

**آزمایشگاه A:** مجموع = 49.8 + 50.3 + 50.1 + 49.9 + 50.2 = 250.3 ← میانگین = **50.06**
- بازه: 49.8 تا 50.3 (پهنای 0.5) ← **دقیق**
- میانگین بسیار نزدیک به ۵۰ ← **صحیح**

**آزمایشگاه B:** مجموع = 44.0 + 57.5 + 51.2 + 46.3 + 52.0 = 251.0 ← میانگین = **50.20**
- بازه: 44.0 تا 57.5 (پهنای 13.5) ← **نادقیق** (خطای تصادفی زیاد)
- میانگین نزدیک ۵۰ ← به‌طور میانگین **صحیح** (سوگیری ندارد)

نتیجه: هر دو آزمایشگاه به‌طور میانگین صحیح‌اند، ولی یک اندازه‌گیری منفرد در B ممکن است تا ۷ واحد خطا داشته باشد. برای تصمیم بالینی روی **یک** بیمار، آزمایشگاه A بسیار قابل‌اعتمادتر است. (معیار عددی پراکندگی، یعنی انحراف معیار و ضریب تغییرات، در M05 آموزش داده می‌شود.)

</details>

**تمرین ۱.۴.۹** — CRP واقعی ۱۰ بیمار (mg/L): 20، 25، 30، 35، 40، 45، 50، 120، 150، 180. سه بیمار بدحال (۱۲۰، ۱۵۰، ۱۸۰) پیش از نمونه‌گیری به ICU بیمارستان دیگری منتقل شدند و CRP آن‌ها ثبت نشد.
(الف) میانگین واقعی و میانگین «بیماران کامل» را حساب کنید. (ب) سوگیری چقدر و در چه جهتی است؟ (ج) سازوکار گمشدگی چیست؟
